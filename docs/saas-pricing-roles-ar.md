## 2) مساحة Vogantra التنافسية

Vogantra لا يجب أن ينافس كـItinerary Builder فقط ولا كـBooking Engine فقط. التموضع الأقوى:

> نظام تشغيل ومالية عربي لشركات السياحة: من أول طلب العميل، للتسعير والحجز والتشغيل، حتى التحصيل وصافي الربح.

عناصر التفوق المقترحة:

- واجهة عربية وRTL ودورة عمل مبنية على أقسام شركة السياحة.
- سعر ثابت للشركة يشمل عدد مستخدمين، بدل رسوم مرتفعة لكل مستخدم.
- لا توجد عمولة على كل حجز داخل Vogantra.
- ربط الـCRM والـSOP والحجوزات والفواتير والحسابات في سجل تشغيلي واحد.
- صلاحيات، عزل بيانات المؤسسات، سجل مراجعة، فروع وهوية مخصصة في الخطط الأعلى.

## 5) تقسيم الـRoles

### مستوى المنصة

| الدور | المسؤولية |
|---|---|
| Platform Owner | ملكية المنصة، إدارة مديري المنصة، الخطط، الإعدادات الحساسة |
| Platform Admin | المؤسسات، الاشتراكات، التحويلات، الدعم، المتابعة بدون تغيير ملكية المنصة |

### مستوى المؤسسة — أدوار أساسية ثابتة

| الدور | المسؤولية |
|---|---|
| Owner | الاشتراك، الفوترة، كل البيانات والصلاحيات |
| Admin | إدارة المؤسسة والفريق والموديولات، بدون التحكم بملكية المنصة |
| Manager | تشغيل الأقسام والتقارير والاعتمادات اليومية |
| Agent | تنفيذ العمل المسموح: عملاء، عروض، حجوزات ومستندات |
| Viewer | قراءة فقط |

### قوالب وظيفية فوق الدور الأساسي

لا نضيف عشرات القيم إلى Enum الـRole. نستخدم `Agent` أو `Manager` كدور أساسي، ثم قالب صلاحيات وظيفي:

| القالب | أهم الصلاحيات |
|---|---|
| خدمة العملاء | إنشاء وتعديل العملاء، Intake، متابعة الطلبات، قراءة الحجز والفاتورة |
| المبيعات | CRM، Pipeline، عروض الأسعار والمتابعة، بدون حسابات كاملة |
| التسعير | طلبات التسعير، الموردون والأسعار، خيارات العرض، بدون دفع أو اعتماد مالي |
| الحجوزات | إنشاء/تعديل/تأكيد/إلغاء الحجوزات، الموردون، المستندات |
| المحاسب | الفواتير، التحصيل، المصروفات، البنوك، تقارير مالية |
| المدير المالي | كل ما سبق + الاعتمادات والتحويلات والتقارير المتقدمة |
| التسويق | WhatsApp والحملات والأتمتة، بدون البيانات المالية |
| المراجع | قراءة وتصدير وسجل مراجعة، بدون إنشاء أو تعديل أو حذف |

هذا التقسيم يحافظ على RBAC بسيط في قاعدة البيانات ويعطي الإدارة صلاحيات دقيقة حسب الوظيفة.
