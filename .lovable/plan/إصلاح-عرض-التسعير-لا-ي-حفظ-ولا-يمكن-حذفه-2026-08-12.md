# إصلاح: عرض التسعير لا يُحفظ ولا يمكن حذفه

## سبب المشكلة (مؤكد من قاعدة البيانات)

عمليات عروض التسعير مقيّدة بقسم «الحجوزات» فقط:

- سياسة الحذف على `sop_pricing_options` تسمح بالحذف فقط لمن هو عضو في قسم `reservations`.
- مُشغّل (trigger) `sop_guard_pricing_option` يمنع الإضافة، ويمنع تعديل حقول السعر/التكلفة/سياسة الإلغاء لأي مستخدم خارج قسم `reservations`.

وبفحص الأعضاء الحاليين: المالكون/المديرون (مثل حساب Mohamed salah بدور owner) غير مسجلين في أي قسم، لذلك تفشل عندهم عمليات الحفظ والحذف رغم امتلاكهم أعلى صلاحية. الموظفة Sarah (قسم reservations) هي الوحيدة القادرة على ذلك.

بالإضافة إلى ذلك: يوجد حد أقصى 3 عروض لكل طلب تسعير، وعند محاولة إضافة عرض رابع تظهر رسالة خطأ إنجليزية غير مفهومة، بدون إمكانية حذف عرض لإفساح مكان.

## الحل

### 1. قاعدة البيانات
- تحديث `sop_guard_pricing_option` ليسمح أيضاً لأدوار `owner` / `admin` / `manager` بالإضافة والتعديل (نفس منطق التجاوز المستخدم سابقاً في استلام الليدات).
- استبدال سياسة الحذف بحيث تسمح لعضو قسم الحجوزات **أو** لأدوار owner/admin/manager داخل نفس المؤسسة.
- منع الحذف بعد اعتماد/نشر التسعير (الطلب في حالة `quoted`/`closed`) حفاظاً على سجل ما تم إرساله للعميل.
- رسالة خطأ عربية واضحة عند تجاوز حد الـ 3 عروض.

### 2. الواجهة
- تأكيد قبل الحذف (نافذة تأكيد بدل الحذف الفوري) مع اسم العرض.
- إخفاء/تعطيل زر الحذف مع سبب واضح عندما يكون الطلب منشوراً.
- عند الوصول لحد 3 عروض: تعطيل زر «إضافة عرض» مع تلميح «الحد الأقصى 3 عروض — احذف عرضاً لإضافة آخر».
- إظهار سبب الرفض بالعربية إن رفضت قاعدة البيانات الحفظ (بدل الرسالة الإنجليزية الحالية).

## التحقق
- الدخول بحساب مالك/مدير: حفظ عرض تسعير جديد وتعديله وحذفه بنجاح.
- الدخول بحساب قسم الحجوزات: نفس السلوك يعمل كما كان.
- حساب مبيعات: لا يستطيع تعديل الأسعار (يظل ممنوعاً كما هو مطلوب).
- بعد النشر: الحذف ممنوع مع رسالة توضيحية.
